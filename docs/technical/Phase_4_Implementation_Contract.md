## Profiles and archive API (core collection worker)

Base save container is existing GamePaths default SaveDirectory (or explicit smoke override). Default profile uses that directory, so existing schema1 session is readable without rewriting. Imported profiles live under <base>/Profiles/<GUID-N> and never overwrite another directory. A small checksummed versioned active-profile pointer chooses a profile on next startup. Own container-wide file lease held by runtime bootstrap for Phase4 lifetime prevents competing activation/publication; SessionStore/PhysicalStore keep their own writer locks. Older player folders remain separate; no automatic migration/copy/read of them.

Frozen core API:

- CollectionProfiles : IDisposable constructor(string baseDirectory); string ActiveProfileId (empty means default); string ActiveDirectory; string Notice; string[] BackupFiles; Dispose(). Validate all paths/reparse ancestors before existence/reads/writes; container metadata never a directory/URI escape.
- CollectionProfiles.CreateBackup(string activeDirectory, IStateSerializer sessionSerializer, IPhysicalSerializer physicalSerializer,Catalog catalog) returns string backupPath. Explicit user-triggered read/export; caller invokes on its owning synchronous thread only after both active snapshots are acknowledged and no error/pending mutation. Backup is a new bounded versioned ZIP under <base>/Backups; immutable membership/checksums; no lock/work/corrupt/provenance/media files. Include state.save/backup/anchor if present and validated physical authoritative files if present. No plaintext provider credentials/assets. A truly empty store may export a validated explicit empty-profile marker; never confuse missing acknowledged content with fresh blank.
- CollectionProfiles.PreviewImport(string backupPath,IStateSerializer,IPhysicalSerializer,Catalog) returns ImportPreview (immutable, read-only operation). It may read only a bounded file inside this container's Backups folder, preserve exact original bytes, validate ZIP paths/member uniqueness/count/size/aggregate caps/hash/schema/pack identity/physical events and reject corruption/unknown versions. It does NOT create a profile or alter selection/state. It pins archive hash/size/active-profile identity and retains detached reviewed bytes.
- ImportPreview read-only: ReceiptId, SourceHash, SourceName strings; VirtualCardCount, PhysicalCardCount, VirtualUnique,PhysicalUnique ints; Physical/virtual revision metadata if useful; string Summary. No original sources/paths leaked in UI errors.
- CollectionProfiles.ConfirmImport(ImportPreview) returns string newProfileId. Only exact owned preview valid; detect archive replacement and active-profile context drift; never parse mutable UI text anew. Create exclusive operation-owned new profile, publish verified bytes without overwriting; validate by actual SessionStore/PhysicalStore in that new profile after extraction (any recovery writes only there), then publish checksummed active pointer. Uncertain acknowledgement uses the same preview/receipt and reconciles existing imported profile rather than creating another. Activation requires explicit confirm; UI becomes restart-required after success, existing current profile left intact. Retain backups/receipt/recovery paths on I/O errors. Do not claim sequential file writes are crash atomic. Safe abandoned staging is not an executable collection.

If raw save validation needs a narrow public inspector in namespace Persistence, add a read-only SessionArchiveValidation helper that reuses existing StateValidation/protocol parsing; do not weaken or bypass existing checks. Compile core and helper together for internal-access tests. Before writing any schema/migration, inspect current files and choose the smallest representation consistent with this contract. No restore-in-place or silent merge.
